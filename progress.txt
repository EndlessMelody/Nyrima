# Nyrima Development Progress Report - Dynamic OAuth & Identity Integration

## Summary of Work: The Subtitle Journey
Throughout this session, we systematically addressed the issue of subtitles not displaying. Here is the full timeline of the subtitle resolution:

1. **Initial Diagnosis (The 403 Error):**
   - Identified that subtitles were failing with a `403 Forbidden` error. 
   - Root cause: The public Google Drive API key was hitting quota limits for private or high-traffic files.

2. **Architectural Shift (OAuth Bypass):**
   - Realized that injecting an OAuth `access_token` into the download request is the only reliable way to bypass these 403 errors.
   - Decided to implement a "Bring Your Own Key" (BYOK) model for the OAuth Client ID to keep the extension lightweight and user-controlled.

3. **UI Integration:**
   - Added an **OAuth Client ID** input field in the User Center (`ApiConfigPanel.tsx`).
   - This allows users to link their own Google Cloud credentials directly through the UI.

4. **Background Logic Refinement (The Silent Flow Fix):**
   - Discovered a critical blocker: The Player Page loads subtitles via a "non-interactive" auth request. Without a cache, this would trigger a silent OAuth flow that Google often rejects without `prompt=none`.
   - **Resolution:** Implemented `customTokenCache` in `service-worker.ts`. Now, once a user clicks "Connect Drive", the token is cached globally in the background script.
   - **Subsequent result:** When the video starts, Nyrima instantly pulls the cached token and fetches the subtitle without any network delays or 403 errors.

5. **Final Implementation Details:**
   - Updated `buildPublicStreamUrl` to support token injection.
   - Refactored `downloadFile` and `getSubtitleText` to be auth-aware.
   - Added `prompt=none` to the dynamic `launchWebAuthFlow` for future-proofing silent re-authentication.

## Technical Accomplishments

### 1. Dynamic OAuth Configuration System
- **Decoupled Auth from Manifest:** Moved away from requiring `client_id` in `manifest.config.ts`.
- **User-Provided Credentials:** Implemented an input field in the `UserCenter` -> `ApiConfigPanel` for users to provide their own Google Cloud OAuth Client ID.
- **Dynamic Auth Flow:** Refactored the background service worker to use `chrome.identity.launchWebAuthFlow`. This allows the extension to use any Client ID provided at runtime instead of being locked to a build-time manifest value.

### 2. User Center & Identity Integration
- **Profile Fetching:** Implemented "Connect Drive" button that triggers the OAuth flow and fetches the user's Google profile (Name and Avatar).
- **Persistent Storage:** Integrated `chrome.storage.local` to securely save the user's API Key, TMDB Key, and OAuth Client ID.
- **Improved UI/UX:** Added validation alerts and clear instructions in the API Settings panel to guide users through creating and linking their own Google Cloud credentials.

### 3. Drive API & Streaming Optimization (Bypassing 403 Errors)
- **Token-Based Streaming:** Updated `buildPublicStreamUrl` and subtitle loading logic to prioritize the OAuth `access_token`. This bypasses the strict rate limits applied to public API keys, resolving "403 Forbidden" issues during playback.
- **Background Token Caching:** Implemented a caching mechanism in `service-worker.ts` for the custom OAuth token. This ensures that non-interactive requests (like loading subtitles when a video starts) succeed instantly without re-prompting the user.
- **Silent Auth Support:** Added `prompt=none` handling for non-interactive auth requests to ensure a seamless background experience.

### 4. Technical Infrastructure
- **New Service:** Created `src/app/services/oauth-key.ts` for standardized management of the OAuth Client ID.
- **Shared Constants:** Updated `src/shared/constants.ts` with new storage keys for OAuth management.
- **Build Stabilization:** Verified that the new dynamic architecture builds and deploys successfully via Vite/TSC.
